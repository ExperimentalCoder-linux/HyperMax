==============================================================================
                              HYPERMAX.NVIM
==============================================================================

HyperMax.nvim is a Neovim plugin for creating and managing coding projects
directly from Neovim.

This manual documents the available commands, keybindings, configuration
options, and health checks.

==============================================================================
1. INTRODUCTION                                           *hypermax-introduction*
==============================================================================

HyperMax.nvim provides tools for creating and managing coding projects without
leaving Neovim.

Its features include:

- Project creation.
- Language selection.
- Project manager selection.
- Project layout management.
- Configuration settings.
- Language and project manager health checks.

==============================================================================
2. INSTALLATION                                           *hypermax-installation*
==============================================================================

Install HyperMax.nvim using your preferred Neovim plugin manager.

For lazy.nvim, add a plugin specification similar to:

    {
        "ExperimentalCoder-linux/HyperMax",
        name = "hypermax.nvim",
        main = "hypermax",
        opts = {
            project_dir = "~/Code",
            create_missing_dir = true,
            open_after_create = false,
            default_language = "c",
        },
    }

After installation, restart Neovim and verify that the plugin loads correctly.

==============================================================================
3. CONFIGURATION                                         *hypermax-configuration*
==============================================================================

HyperMax initializes automatically through plugin/hypermax.lua. You do not
need to call setup() to make the plugin work. The optional setup() function
only validates and stores configuration; it does not register commands,
keymaps, autocmds, or feature modules.

Configuration is merged in this order, from lowest to highest priority:

1. Built-in defaults.
2. Previously saved global settings.
3. The vim.g.hypermax table (or a function returning a table).
4. The table passed to require("hypermax").setup({...}).

Example:

    vim.g.hypermax = {
        project_dir = "~/Code",
        default_language = "cpp",
    }

    require("hypermax").setup({
        open_after_create = false,
        default_keymaps = false,
    })

Invalid fields and unknown option names are reported and ignored. Use
:HyperMax settings to edit persisted global preferences, or :HyperMax config
to inspect the active configuration.

GLOBAL OPTIONS

                                                        *hypermax-project-dir*
project_dir
    Parent directory for newly created projects. Default: ~/Projects.

                                            *hypermax-create-missing-dir*
create_missing_dir
    Create project_dir when it does not exist. Default: true.

                                             *hypermax-open-after-create*
open_after_create
    Open a project after it has been created. Default: true.

                                           *hypermax-default-language*
default_language
    Language registry ID selected by default. Default: cpp.

                                            *hypermax-default-manager*
default_manager
    Project-manager registry ID selected by default for the active language.
    Default: native.

                                             *hypermax-default-layout*
default_layout
    ID of the layout selected by default during project creation. An empty
    string selects no preferred layout. Default: empty.

                                       *hypermax-favourite-languages*
favourite_languages
    Array of language IDs displayed before other languages. Default: cpp, c,
    lua, python, rust. The value must be a dense array containing only
    non-empty strings.

                                      *hypermax-remember-last-project*
remember_last_project
    Remember the most recently opened project. Default: true.

                                           *hypermax-show-progress*
show_progress
    Show the project-creation progress window. Default: true.

                                    *hypermax-show-command-output*
show_command_output
    Show output from project-generation commands. Default: true.

                                  *hypermax-confirm-before-create*
confirm_before_create
    Ask for confirmation before creating a project. Default: true.

                                          *hypermax-create-readme*
create_readme
    Generate a README.md file for new projects. Default: true.

                                       *hypermax-create-gitignore*
create_gitignore
    Generate a .gitignore file for new projects. Default: true.

                                        *hypermax-create-credits*
create_credits
    Generate a CREDITS.md file for new projects. Default: true.

                           *hypermax-create-default-directories*
create_default_directories
    Create the directories supplied by the selected language/layout. Default:
    true.

                                  *hypermax-remember-last-language*
remember_last_language
    Remember the last selected language. Default: true.

                                   *hypermax-remember-last-manager*
remember_last_manager
    Remember the last selected project manager. Default: true.

                                         *hypermax-default-keymaps*
default_keymaps
    Install only the minimal <Leader>++ mapping to open the workspace. The
    mapping is not installed if another mapping already owns that key. Set
    this to false to disable HyperMax's default global mapping. Default: true.

                                             *hypermax-last-project-path*
last_project_path
    Managed value containing the most recently opened project path. HyperMax
    updates this when remember_last_project is enabled. It is included in
    the configuration schema for persistence and migration; normally it does
    not need to be set manually. Default: empty.

==============================================================================
4. KEYBINDINGS                                             *hypermax-keybindings*
==============================================================================

HyperMax exposes namespaced <Plug> mappings for all major actions. By default,
it registers only one global mapping: <Leader>++ opens the workspace. The
default is not installed if the user already owns that mapping. Set
|g:hypermax| or setup() option default_keymaps to false to disable it.

Example user mappings: >lua
    vim.keymap.set("n", "<leader>hp", "<Plug>(HyperMax-CreateProject)")
    vim.keymap.set("n", "<leader>ht", "<Plug>(HyperMax-Tasks)")
    vim.keymap.set("n", "<leader>hh", "<Plug>(HyperMax-History)")
<

Available mappings use the <Plug>(HyperMax-Name) form:

    Menu                 Open the workspace.
    CreateProject        Open the project creation wizard.
    ListProjects         List registered projects.
    OpenLastProject      Open the most recently opened project.
    QuickCreateProject   Create a project using preferred defaults.
    SaveLayout           Capture the current directory as a layout.
    EditLayout           Edit a saved layout.
    LoadLayout           Apply a saved layout.
    ListLayouts          Choose a layout for project creation.
    Settings             Open settings.
    Workspace            Open the workspace.
    Palette              Open the command palette.
    Tasks                Open the current project's task board.
    Runs                 Open project run configurations.
    Diagnostics          Show project-scoped diagnostics.
    History              Browse save points and rollbacks.
    SavePoint            Create a hard save point.
    Tutorial             Open the tutorial menu.
    Health               Run :checkhealth hypermax.
    ConvertProject       Convert a directory into a HyperMax project.
    UndoConversion       Undo folder conversion.
    ScrapeProject        Remove project metadata with a backup.
    ShowConfig           Print the active configuration.

The <Plug> mappings do not create a user's preferred key layout. Map only the
actions you use. HyperMax checks for existing mappings before creating its
optional default <Leader>++ mapping and never replaces a user-owned mapping.
No other global feature shortcuts are installed automatically.

==============================================================================
5. COMMANDS                                                  *hypermax-commands*
==============================================================================

HyperMax provides one scoped user command. Type :HyperMax followed by <Tab>
for subcommand completion. Nested command groups also complete their own
actions. Running :HyperMax without arguments opens the workspace. HyperMax does not
replace an existing user command with that name. If a collision exists, the
rest of the plugin still initializes and its <Plug> mappings remain available.

                                                    *:HyperMax*
:HyperMax
    Open the workspace.

                                                    *:HyperMax-project*
:HyperMax project create
    Start the project creation wizard.

:HyperMax project list
    List registered projects.

:HyperMax project open-last
    Open the most recently opened project.

:HyperMax project quick-create
    Create a project using preferred defaults.

:HyperMax project convert [directory]
    Add HyperMax metadata to an existing directory.

:HyperMax project undo-conversion [directory]
    Undo a folder conversion while preserving its files.

:HyperMax project scrape [directory]
    Remove HyperMax metadata after creating a backup.

                                                    *:HyperMax-layout*
:HyperMax layout save
    Capture the current directory and open an editable layout JSON draft.

:HyperMax layout edit
    Choose an existing saved layout and edit its JSON draft.

:HyperMax layout load
    Choose and apply a saved layout.

:HyperMax layout list
    Choose a saved layout to use for project creation.

                                                    *:HyperMax-workspace*
:HyperMax workspace [open]
    Open the workspace home.

:HyperMax workspace palette
    Open the action picker.

:HyperMax workspace tasks
    Open the current project's task board.

:HyperMax workspace runs
    Manage project run configurations.

:HyperMax workspace diagnostics
    Collect current project diagnostics into quickfix.

                                                    *:HyperMax-history*
:HyperMax history [open]
    Browse save points and rollbacks.

:HyperMax history save
    Create a manual hard save point.

:HyperMax settings
    Open HyperMax settings.

:HyperMax config
    Display the active configuration.

:HyperMax tutorial
    Open the Essentials and Advanced tutorial selector.

:HyperMax health
    Run :checkhealth hypermax.

The layout-draft buffer also provides buffer-local :HyperMaxLayoutSave and
:HyperMaxLayoutCancel commands to validate/save or discard the current draft.

Global per-action commands from earlier releases have been consolidated under
:HyperMax. Use the subcommand tree above for all global actions.

==============================================================================
6. WORKSPACE AND FLOW                                          *hypermax-workspace*
==============================================================================

Open the central workspace with :HyperMax workspace. It shows
project identity, Git change count, open-task count, run configurations and
current diagnostic counts. Its shortcuts open project switching, the project
explorer, task board, run configurations, file finding, text search, TODO
scanning, project-scoped diagnostics, Git status, layouts, settings and health
checks. Use :HyperMax workspace diagnostics to open diagnostics for
files under the project root in quickfix.

The command palette is available with :HyperMax workspace palette.
It uses vim.ui.select, so compatible selector plugins can provide fuzzy
selection and custom presentation.

TASK BOARD

    Open with :HyperMax workspace tasks. A task has a title, optional
    details, priority (low, normal or high) and status (todo, doing or done).

    a       Add a task.
    e       Edit the selected task.
    s       Move the task to the next status.
    p       Cycle priority.
    P       Pin or unpin the selected task in the persistent pinned section.
    d       Mark done or return to todo.
    x       Delete after confirmation.
    Enter   Display task details.

    The pinned section is positioned at the top or bottom of the board using
    the project's pinned_tasks_position setting in .hmc/config.json.

RUN CONFIGURATIONS

    Open with :HyperMax workspace runs. Add named build, test, format or
    launch commands. Each runner has a project-relative working directory.
    Press Enter or r to run the selected configuration in a terminal split.

    Commands are explicitly user-authored shell commands. Review them before
    running configurations from untrusted projects. Working directories must
    exist and are checked against real paths to prevent symlink escapes from
    the project root.

Both tasks and run configurations are saved in .hmc/workspace.json. This is
project-specific state and is deliberately excluded from reusable layouts.
After a runner exits with code zero, HyperMax creates a soft save point unless
auto_save_after_success is disabled in the project settings.

SAVE HISTORY AND ROLLBACK

    Use :HyperMax history save to create a hard save. Use :HyperMax history
    to open the save-history context window. Press s to
    create a hard save, Enter to restore the selected point, d to delete it,
    r to refresh, and q or Escape to close the window. Restore operations are
    confirmed and create a safety save before changing files. Rollback is
    refused if the target or current workspace cannot be captured completely.

    Snapshots include normal project files and .hmc project configuration, but
    exclude .git and .hmc/history. File/directory permissions and symbolic
    links are preserved. Brotli is used when the brotli executable is present;
    without it, save points use uncompressed files.

PROJECT WORKSPACE SETTINGS

    Project-specific settings are stored in .hmc/config.json, separately from
    global project-generation preferences. They include a custom entry-point
    file/function, hidden-file visibility, relative file/folder exclusions,
    tabline visibility, context-window placement, pinned-task placement and
    automatic soft saves after successful runs. The dashboard h key toggles
    hidden files and saves the setting for that project. The .git and .hmc
    metadata directories remain protected from the explorer; other hidden
    folders such as .venv are revealed when hidden items are enabled.

    Settings are grouped into nested Project creation, Saving and history,
    Layouts, Interface, Utilities, Global settings and Workspace menus. Nested
    menus provide a Back entry. Workspace-only settings are shown only when a
    HyperMax project is available.

CONTEXT WINDOW PLACEMENT

    HyperMax context windows share one placement helper. The context_position
    setting accepts N, E, S, W, NE, NW, SE, SW, NS, EW and center. Cardinal
    values anchor a window to an editor edge, corner values anchor it to a
    corner, and NS/EW/center place it in the middle. Window dimensions are
    clamped to the editor size.

SEARCH AND NAVIGATION

    The workspace file picker uses ripgrep when installed; otherwise
    HyperMax uses a bounded filesystem scan that skips common dependency and
    build directories.

    Project text search prompts for a query and sends matches to quickfix using
    ripgrep. Project diagnostics collect current Neovim diagnostics from buffers
    inside the project into the quickfix list. Git status is available from
    the workspace home and opens
    in a terminal rooted at the project. The buffer switcher lists named,
    listed buffers in the current Neovim instance.

==============================================================================
7. PROJECT MANAGEMENT                                         *hypermax-projects*
==============================================================================

HyperMax provides project creation and management functions through its
menu and keybindings.

PROJECT CREATION

    Use :HyperMax project create to start the project wizard.

    Use :HyperMax project quick-create to create a project using preferred defaults.

PROJECT LIST

    Use :HyperMax project list to open the project list.

PROJECT REGISTRY

    A folder becomes a registered project when it is created through HyperMax
    or converted using :HyperMax project convert. The global registry is independent of
    project_dir, so projects can be listed even when they live elsewhere.

LAST PROJECT

    Use :HyperMax project open-last to open the most recently registered project.
    Use :HyperMax project list to browse all registered projects.

The exact available project actions depend on the functions implemented by
the installed version of HyperMax.nvim.

==============================================================================
8. LAYOUTS                                                    *hypermax-layouts*
==============================================================================

HyperMax supports saving and loading project layouts.

SAVE A LAYOUT

    Use :HyperMax layout save to save the current directory as a layout.

LOAD A LAYOUT

    Use :HyperMax layout load to load a saved layout.

Layouts preserve project-relative directory paths and text file contents.
Saving a layout opens a temporary JSON draft in the editor so you can create,
remove, or edit entries before the template is persisted. Use :write or
:HyperMaxLayoutSave to validate and save it; use :HyperMaxLayoutCancel to
cancel the draft. The :HyperMax layout edit command opens an existing template.

The .hmc project metadata, Git metadata, common build/cache directories,
binary files, credential files, and files larger than 4 MiB are excluded from
reusable layouts. Safe hidden files such as .gitignore and .editorconfig remain.

User layouts are stored globally in Neovim's data directory. Project metadata
and its file-tree snapshot remain inside each project's own .hmc directory.

==============================================================================
9. HEALTH CHECKS                                                *hypermax-health*
==============================================================================

HyperMax integrates with Neovim's standard health-check system. Run:

    :checkhealth hypermax

The report checks:

- Neovim version compatibility and runtime initialization.
- Global configuration types and the configured project directory.
- Access to Neovim's data directory.
- Optional external tools such as Git, ripgrep and Brotli.
- Registered language and project-manager executables, including the selected
  default language and manager.

The scoped |:HyperMax health| subcommand invokes |:checkhealth| hypermax.
Developer tests are separate from this health report. Run Busted unit specs
with `busted --verbose spec`, then run the Neovim integration suite with:

    nvim --headless -u NONE -c "set rtp+=." -c "luafile tests/run.lua"

==============================================================================
10. TROUBLESHOOTING                                     *hypermax-troubleshooting*
==============================================================================

PLUGIN NOT LOADING

    Verify that the repository is installed with this structure:

        hypermax.nvim/
        |-- doc/
        |-- lua/
        |   `-- hypermax/
        |       |-- init.lua
        |       |-- config.lua
        |       |-- health.lua
        |       |-- commands.lua
        |       |-- keymaps.lua
        |       |-- languages.lua
        |       |-- layouts.lua
        |       |-- managers.lua
        |       |-- project.lua
        |       `-- settings.lua
        |-- plugin/
        `-- tests/

    The lua/hypermax/ directory must be directly inside the plugin root.

DOCUMENTATION ERRORS

    Neovim help documentation uses .txt files inside the doc/ directory.

    This file provides the native help entry for HyperMax.nvim. The Markdown
    README can remain alongside it.

COMMAND NOT FOUND

    Confirm that the plugin loaded successfully and that the command is
    registered by the installed version.

11. TUTORIALS                                                   *hypermax-tutorials*
===============================================================================

HyperMax displays the Essentials welcome lesson once on the first startup
following installation. The one-time marker is stored in
stdpath("data")/hypermax/tutorial_progress.json, independently of the plugin
version. Updating HyperMax therefore does not reopen first-run onboarding.

Open the selector with :HyperMax tutorial or from the workspace home. The
selector contains two independent tracks:

ESSENTIALS
    Projects, dashboard navigation, file editing, tasks, run configurations,
    settings, and the everyday commands.

ADVANCED
    Reusable layouts, Git integration, save points and rollback, diagnostics,
    workspace settings, pinned tasks in the editor, and project search.

Within a lesson, press c to mark it complete or incomplete, n/p to navigate,
and b to return to the lesson list. Press r in a track list to reset that
track's progress only. Essentials and Advanced progress are stored separately.

Pinned tasks
    In :HyperMax workspace tasks, select a task and press P. Pinned tasks are displayed in
the editor winbar for buffers belonging to that project and remain visible
while scrolling. Press P again to unpin a task.
